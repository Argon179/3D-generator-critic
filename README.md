# GAI · 3D Loop — первая версия

Локальный эксперимент: **Stable Fast 3D / многовидовая реконструкция → Blender EEVEE → Qwen3-VL-4B-Instruct + проверка 3D → TextDeformer → повторная проверка**.

Репозиторий: [Argon179/3D-generator-critic](https://github.com/Argon179/3D-generator-critic). Результаты реального запуска и измерения: [docs/VALIDATION.md](docs/VALIDATION.md). Новая реконструкция, метрики и проверка этапов: [docs/MULTIVIEW_VALIDATION.md](docs/MULTIVIEW_VALIDATION.md). Проверка плоских моделей и её ограничения: [docs/VOLUME_VALIDATION.md](docs/VOLUME_VALIDATION.md).

В Git хранятся исходники, конфигурация, тесты и описания источников изображений. Окружения, инструменты, веса, токены, фотографии из сторонних наборов и результаты запусков остаются локальными. Для новой копии репозитория нужны подготовка окружений по инструкции ниже и собственные фотографии либо загрузка изображений из источников в `reference_images/**/sources.json` с соблюдением условий соответствующего набора.

## Запуск на этом компьютере

```bash
cd "/home/msi/Рабочий стол/Учёба/GAI"
./run.sh
```

Открыть **http://127.0.0.1:7860**. Для другого порта: `GAI_PORT=7861 ./run.sh`.

Запускать из обычного терминала. В песочнице агента `/dev/nvidia*` скрыты; это не неисправность драйвера. На хосте проверены RTX 4070 Laptop, 8188 MiB VRAM и PyTorch 2.5.1+cu121.

В интерфейсе:

1. Выберите объект или загрузите 2–12 фотографий **одного и того же** объекта.
2. Галочками выберите проверочные ракурсы; кружком — одно фото, по которому SF3D построит сетку.
3. Укажите короткое английское описание объекта. Выберите способ удаления фона. Для COIL-100 используется чёрный фон; для остальных — U²-Net/rembg либо готовые RGBA-файлы.
4. Для начала выберите «Только оценка», затем попробуйте одну правку. Один и тот же seed не гарантирует побитовую воспроизводимость CUDA.
5. Просматривайте модель, пары референс/рендер, замечания, метрики, историю правок и журнал. GLB скачивается по кнопке; исходный SF3D GLB с текстурами остаётся в файлах запуска.

## Модели и окружения

| Компонент | Назначение | Локальное окружение |
|---|---|---|
| [Stable Fast 3D](https://github.com/Stability-AI/stable-fast-3d) | Одно фото → исходная GLB-сетка | `.venvs/sf3d` |
| Многовидовая реконструкция | Известные азимуты и силуэты → внешний объём, SDF + marching cubes | `.venv`, CPU, scikit-image |
| [Blender 4.5.14 LTS](https://download.blender.org/release/Blender4.5/) | EEVEE, прозрачный фон и clay-материал | `tools/blender` |
| [Qwen3-VL-4B-Instruct](https://huggingface.co/Qwen/Qwen3-VL-4B-Instruct) | Сравнение до трёх пар изображений, JSON-замечания | `.venvs/qwen`, NF4, double quant, FP16 compute |
| [TextDeformer](https://github.com/threedle/TextDeformer) | Изменение сетки по исходному и целевому описаниям | `.venvs/textdeformer` |
| U²-Net / rembg | Маска объекта на CPU | Окружение SF3D |
| FastAPI + Canvas | Интерфейс, запуск задач и просмотр геометрии | `.venv` |

Модельные окружения созданы поверх существующего `/home/msi/anaconda3/envs/dl` с `--system-site-packages`, чтобы не копировать несколько гигабайт PyTorch/CUDA. Само окружение `dl` не изменялось. Его нельзя удалять, пока используются эти venv. Все новые пакеты, модели и инструменты размещены в проекте; временные скомпилированные ядра TextDeformer находятся в `/tmp/gai-extensions-*` и при необходимости пересобираются.

Исходники зафиксированы в `configs/upstream-lock.json`, ревизии весов — в `configs/project.json`. SF3D требует Transformers 4.42.3, Qwen — 4.57.1, поэтому окружения разделены. Для Python 3.12 вместо сломанного исходного пакета `gpytoolbox==0.2.0` используется 0.3.7. Для старого CLIP зафиксирован setuptools 75.8.2. `torch-sparse` и `torch-scatter` установлены из колёс PyG для torch 2.5 / cu121.

Полный checkpoint SF3D содержит также параметры DINOv2 и OpenCLIP. Обёртка создаёт их архитектуры без повторного скачивания базовых весов, затем SF3D строго загружает все параметры из своего checkpoint. Инференс со случайными весами не используется. Для libigl адаптирована новая сигнатура `random_points_on_mesh`.

Для CUDA-расширений подготовлен локально распакованный g++-12 (`tools/compiler`). Системные пакеты/драйвер не заменялись. Python-обёртка создаёт безопасный для Ninja путь к компилятору без пробелов в `/tmp`.

## Просмотр этапов

В поле **«Этап эксперимента»** доступны входные фото, все SF3D-кандидаты, многовидовая реконструкция (если выполнялась), рендеры/метрики, критик и TextDeformer каждой итерации. Поле **«Модель этапа»** переключает сохранённые GLB/OBJ; просмотр нормирует размер и показывает геометрию. Полные исходники доступны по ссылкам. Сопоставление фото/рендеров показывается только для той модели, для которой оно действительно вычислено; при переключении на другой кандидат оно скрывается. JSON-параметры и отчёты раскрываются отдельно, полный журнал доступен на каждом этапе. Старые запуски тоже можно просматривать.

## Многовидовая генерация

Режим «Авто» при наличии минимум пяти выбранных фото с известными азимутами строит отдельную **visual hull**: пересечение силуэтов в приближённой ортографической камере. SF3D запускается и сохраняется как исходный вариант, а объём восстанавливается по нескольким настоящим фото. Четверть выбранных ракурсов (минимум один), распределённая по серии, не участвует в построении. Известные углы сейчас есть у COIL-100. Для произвольных загрузок и серий без известных углов автоматически остаётся SF3D; номера кадров не трактуются как углы.

Камера, центрирование и масштаб по высоте приблизительные. Этот метод восстанавливает внешний объём; он не восстанавливает невидимые впадины, мелкие детали лица и PBR-текстуры. Это отдельный способ реконструкции, а не дообученный SF3D. Его GLB и исходный SF3D GLB доступны по отдельности в этапах. Наличие объёма не означает точного восстановления.

## Как устроена проверка

- В режиме «Только Stable Fast 3D» SF3D сначала получает выбранное фото. Если сетка подозрительно тонкая, генератор пробует до двух других выбранных фото по одному и сохраняет кандидаты. Из них выбирается сетка с наибольшим отношением толщины к размеру по главным осям. Это эвристика, которая может выбрать объёмную, но неверную форму; точность проверяется отдельно. Если все кандидаты плоские, дефект остаётся явно отмеченным. SF3D не является многовидовым реконструктором. Все снимки, которые использовались в попытках генерации, исключаются из проверочных видов при принятии правки; выбор и измерения записываются в `generation_quality.json`.
- В геометрической копии свариваются вершины на UV-швах. Если основной связный компонент содержит не менее 98% граней, мелкие отдельные фрагменты удаляются. Если остаётся несколько крупных несвязных частей, автоматическая правка пропускается: разреженный решатель требует связной сетки. Исходный GLB не изменяется.
- Сетка приводится к Y-up, центрируется, максимальная сторона становится равной 2. Большие сетки упрощаются до 12 000 треугольников перед разреженным решателем TextDeformer.
- EEVEE рендерит 36 видов: азимут через 30°, высота 0°, 20°, 40°, плюс один вид строго сверху. Обзор ортографический. В сравнении используется clay-материал, чтобы цвет не подменял геометрию. Критик дополнительно всегда получает четыре ортогональных боковых вида и верхний вид, независимо от подбора камеры по референсу. Эти виды показаны отдельно в интерфейсе.
- Независимая проверка геометрии измеряет отношение разбросов поверхности по главной малой и большой осям. Используются точные моменты треугольной поверхности с весами по площади; результат не зависит от поворота, масштаба и плотности вершин. Отношение ниже 0.12 отмечается как сильная плоскостность, ниже 0.35 — как подозрительная малая толщина. Это эвристика: тонкая инженерная деталь может быть правильной. Предупреждение не скрывается даже при несогласии VLM или несоответствии камеры. Автоматическая CLIP-деформация в этом случае останавливается, поскольку она не является надёжным способом восстановить отсутствующую сторону.
- Для COIL-100 ищется общий поворот, направление обхода и высота с учётом известных относительных азимутов. Для данных без углов ищется ближайший силуэт независимо; это менее надёжно.
- После исходной итерации соответствия фиксируются: кандидат оценивается при тех же камерах. Сдвиг и масштаб масок нормированы; метрика не проверяет абсолютные размеры.
- Qwen получает референсы и соответствующие clay-рендеры. Если он указывает несоответствие камеры, низкую уверенность или отсутствие необходимой правки, редактирование пропускается.
- Qwen формирует короткие английские **описания объектов** для CLIP. TextDeformer не является универсальным исполнителем команд «передвинь вершину на N миллиметров».
- Дополнительно вычисляются F1 границы с допуском 2 пикселя на маске 128×128, симметричное среднее расстояние контуров в долях диагонали, замкнутость/согласованность нормалей, число компонентов, объём (только для замкнутой сетки), отношение к объёму выпуклой оболочки и доля площади самого большого плоского среза. Это разные диагностические признаки, не одна «оценка правильности 3D».
- Изменение принимается, если средний IoU **проверочных** видов вырос минимум на 0.005, а ухудшение любого проверочного вида не превысило 0.03. Помимо этого F1 не должен ухудшиться в среднем больше чем на 0.01, расстояние контуров — больше чем на 0.002 диагонали. Рост крупного плоского среза и усиление плоскостности отклоняют правку. VLM дополнительно проверяет форму. Это критерии контроля регрессий, не доказательство правильности 3D. Если VLM утверждает плоскостность, а измеренные признаки её не подтверждают, интерфейс показывает расхождение и автоправка останавливается; исходный ответ VLM не заменяется. При отклонении предыдущий GLB остаётся лучшим.
- Каждый тяжёлый этап — отдельный последовательный subprocess. После завершения процесса его VRAM освобождается. Остановка завершает и дочерние процессы. Есть файловая блокировка GPU между экземплярами проекта.

## Ограничения первой версии

- Требуется хорошо выделенный объект. Для шестерни/гайки VGM-6D сначала желательно подготовить маски детали: автоматическое удаление фона может оставить платформу. Общая область ROI в интерфейсе не заменяет индивидуальные маски при движении предмета.
- Режимы однотонного фона рассчитаны на простые фигурки: берётся главный связный контур, внутренние тёмные области заполняются. Для деталей с отверстиями используйте проверенные RGBA-маски или U²-Net с ручной проверкой.
- COIL-100: исходные фото 128×128, подходят для грубой формы. Серия леопарда крупнее, но содержит ярлычок и кольцо.
- Согласование камеры приблизительное: нет полной оценки перспективы, фокусного расстояния, позы и высоты для каждого фото. Изображения с сильной перспективой могут давать ложные замечания.
- TextDeformer может изменить лишние части и не гарантирует сохранение мелких деталей, текстур, топологии допустимой для печати или инженерных размеров. Итоговый `best.glb` — геометрия, не восстановленные PBR-материалы.
- Камера/IoU не оценивают скрытые стороны. Для инженерных деталей количество зубьев, размеры и резьбу нужно проверять параметрически.
- Первые GPU-запуски могут быть медленнее из-за компиляции ядер; TextDeformer со старыми исследовательскими зависимостями считается экспериментальным.
- Повторная генерация по другому фото не гарантирует восстановления объёма. На маленьких фотографиях COIL-100 SF3D может возвращать почти плоскую сетку с высоким IoU силуэта. Статус «Завершён» означает завершение расчёта, а не подтверждение качества формы.

## Диагностика и проверки

```bash
.venv/bin/python scripts/doctor.py
.venv/bin/python -m pytest -q
.venv/bin/python scripts/smoke_render.py
```

`smoke_render.py` создаёт **техническую тестовую сетку**, делает четыре реальных EEVEE-рендера и проверяет roundtrip силуэтов. Он не имитирует генерацию нейросетью и не выдаёт фиктивную критику. Результат — `runs/_smoke/test_report.json`. Тесты API и метрик выполняются в обычном терминале, поскольку песочница ограничивает потоки/локальные сокеты TestClient.

## Установка из GitHub (Linux x86_64)

Нужны Python 3.12, Git, работающий драйвер NVIDIA, CUDA Toolkit с `nvcc`, совместимый C++-компилятор и Python-окружение с `torch==2.5.1+cu121`, `torchvision==0.20.1+cu121`. CUDA 12.0 на текущем компьютере проверена с g++-12. Локальный `tools/compiler` в Git не входит; на новой машине используйте установленный совместимый компилятор (`CC`, `CXX`, `CUDAHOSTCXX`). Скрипты не устанавливают драйвер, CUDA и системные пакеты.

```bash
git clone https://github.com/Argon179/3D-generator-critic.git
cd 3D-generator-critic
python3 scripts/bootstrap.py --plan
python3 scripts/bootstrap.py
/path/to/torch/python scripts/setup.py --component all
./login-hf.sh
.venvs/qwen/bin/python scripts/download_models.py
.venv/bin/python scripts/doctor.py
./run.sh
```

Замените `/path/to/torch/python` на Python подготовленного окружения. `bootstrap.py` использует только стандартную библиотеку Python 3.12: скачивает две зафиксированные Git-ревизии и официальный Blender, проверяет SHA256 перед распаковкой. Повторный запуск проверяет существующие версии; другую ревизию и локальные изменения в `vendor` он не перезаписывает. `--plan` ничего не скачивает и не записывает. Можно выбрать `--component sources` или `--component blender`. На чистой установке загрузите собственные фотографии через интерфейс; локальные примеры и история запусков автоматически из Git не появятся.

Для воспроизведения окружений на этом компьютере:

```bash
/home/msi/anaconda3/envs/dl/bin/python scripts/setup.py --component all
```

`setup.py` проверяет версии PyTorch/torchvision и наличие исходников до установки пакетов, затем создаёт изолированные окружения. Для переноса на другой компьютер подготовьте совместимый PyTorch, CUDA Toolkit и C++-компилятор; нестандартные пути меняются в `configs/project.json`. Архитектура CUDA для сборки SF3D по умолчанию — 8.9 (RTX 4070); для другой GPU её нужно задать через `TORCH_CUDA_ARCH_LIST`.

В `runs/<id>/iteration_00/generated.glb` — исходная модель SF3D с материалами. В каждой итерации сохраняются `renders/`, `metrics.json`, `critique.json`, сырой ответ Qwen и конфигурации этапов; у правок дополнительно `textdeformer/`. В случае ошибки есть `process.log` и `error.txt`.

### Генерация по нескольким фотографиям: Hunyuan3D-2mv и DA3

В списке генераторов доступны два отдельных режима. Они не запускают SF3D и
не подменяют ошибку результатом другого генератора:

- **Hunyuan3D-2mv** — генерация геометрии по 2–4 сторонам объекта. Для набора
  с известными азимутами выбираются виды 0/90/180/270° относительно главного
  фото с допуском 20°. Главное фото должно показывать переднюю сторону.
  Для загруженных фото раскройте «Стороны для Hunyuan» и назначьте стороны
  вручную. Минимум одно дополнительное фото нужно оставить для проверки.
- **DA3 Base + Poisson** — экспериментальная реконструкция по реальным фото.
  Около четверти снимков зарезервированы для проверки. Модель оценивает
  камеры и глубину; после фильтрации фона облако точек объединяется в сетку
  методом Poisson. Это не CAD: масштаб произвольный, заполнение невидимых
  областей и отверстий требует проверки. При плохих камерах возможны
  пересечения и лишние поверхности.

Для установки используются отдельные `.venvs/hunyuan` и `.venvs/da3`.
Существующие окружения не меняются. Python должен наследовать установленный
PyTorch 2.5.1 + CUDA 12.1:

```bash
.venvs/sf3d/bin/python scripts/setup_multiview.py --download
# Можно устанавливать отдельно:
.venvs/sf3d/bin/python scripts/setup_multiview.py --component da3 --download
```

Исходники клонируются только из официальных репозиториев; их commit сохраняется
в `configs/multiview-upstream-lock.json`. Веса и авторизация используют общий
локальный `HF_HOME`. Загружается FP16 checkpoint формы Hunyuan без текстурного
генератора и DA3 Base. Для Hunyuan применяется CPU offload, построение модулей
сразу в FP16 и извлечение поверхности 256³; DA3 обрабатывает фото при 336 px.
Модели выполняются отдельными процессами, освобождая GPU перед критиком.

Выбор входных видов, отложенные снимки, подготовленные маски, исходный GLB,
время и пиковая VRAM доступны через выбор этапа. DA3 дополнительно сохраняет
карты глубины PNG, камеры/глубину `depth_cameras.npz` и облако `points.ply`.
Наличие файлов весов не гарантирует успешный GPU-запуск. Ошибки и отсутствие
памяти видны в журнале; автоматической подмены другим методом нет.

Официальные источники: [Hunyuan3D-2](https://github.com/Tencent-Hunyuan/Hunyuan3D-2),
[Depth Anything 3](https://github.com/ByteDance-Seed/Depth-Anything-3).

Для встроенной уточки передний вид — 270°, для кошки — 0°. При выборе
Hunyuan интерфейс назначает этот снимок главным. Для остальных наборов
переднюю сторону нужно проверить вручную. Угол 0° в наборе фотографий
не обязательно означает вид спереди.

Разметка сторон доступна прямо под каждой фотографией в режиме Hunyuan:
«Спереди», «Слева», «Сзади», «Справа» или «Для проверки». Назначение стороны
автоматически включает снимок; назначение переднего вида также делает его
главным. Повторное назначение той же стороны переносит метку на новое фото.
Счётчик под карточками показывает число входных сторон и проверочных снимков.
При ручной разметке достаточно двух сторон (обязательно передний вид) и одного
дополнительного фото для проверки; известные азимуты не требуются. Разметка
сохраняется в параметрах запуска и восстанавливается при открытии из истории.
